# Owned full-budget GPU RBM execution

This is an additional locally trained family intended to complement the existing
own-model blend. It has not produced a score. It never consumes downloaded
prediction features or recovered qualifying outcomes.

`scripts/upstream_factored_rbm_execution.py --start` creates one immutable run.
Importing either execution module does not launch work. The controller waits for
the complete independently verified original 1,200-factor run and the existing
own15 trajectory pipeline. It then holds both original primary and GPU lanes.
It does not displace any current numerical process.

The frozen recipe is H400, factor rank 50, seed128, 500 nonempty users per batch,
15 complete epochs for each of the known and qualifying models, source-equivalent
bipolar/CD mathematics, and all raw histories and conditional query addresses.
The own NumPy/Torch random realization differs from Rust's StdRng. No claim of
native training bit identity is made. All seven learned predictive tensors are
retained, including every user and observed training-day bias.

Seven separate owned processes perform full original63 data admission, fresh
runtime actual-MPS/full-width mathematical preflight, known fitting, independent
known model replay, qualifying fitting, independent qualifying model replay,
and final paired assembly. The preflight must prove actual MPS with fallback and
fast math disabled before importing Torch. CPU synthetic tests cannot authorize
production. The independent replay loads the saved complete model and requires
every native prediction bit and every known projection bit to match. All15 epoch
receipts, original data identities, recipe, source, runtime versions, owner,
watchdog, baseline and preceding phase hashes are bound in the receipts.

Data and assembly workers have a 3GiB physical/RSS cap; GPU workers have an 8GiB
physical/RSS/driver cap. Aggregate research physical memory and RSS remain below
24GiB; compressor below5GiB with admission below4.5GiB; swap growth at most128MiB
from one original baseline; free disk at least18.75GiB plus output reservation.
Three stable samples precede dispatch or continuation. Output reservation is
computed from the actual full predictive model dimensions and all native and
projected vectors. Durable payload writes are bounded, exclusive and fsynced;
failed staging files remain intact.

Resource pressure suspends the same dedicated process group inside its existing
batch, RNG, model and write call stack. The original supervisor and watchdog
remain alive holding the original lanes. Continuation requires the same process
identity, unchanged sources and baseline, original caps and three stable samples.
There is no automatic restart, partial-epoch retry, reduced batch/history/epoch
budget, cap increase or baseline reset. Owner loss makes the watchdog stop the
exact original child and retain both inherited lane locks until that child is
terminal. Such failure requires explicit same-process recovery work rather than
another `--start` invocation.

The final paired receipt proves provenance and reproducibility, not accuracy.
Its full known and qualifying vectors must subsequently enter a known-label-only
blend fit, coefficient/vector freeze and independent recovered-group audit.
Recovered scores are adaptive audits and are not official untouched Test scores.
The goal remains below0.85725 on both recovered groups.
